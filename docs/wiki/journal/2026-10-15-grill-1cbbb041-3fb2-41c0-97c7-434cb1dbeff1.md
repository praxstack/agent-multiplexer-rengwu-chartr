## Question 15

```text
Round: Simpler agent attention
Question: Which detection approach should we pursue?
Description (Markdown source):
**Existing Herdr detection:** uses the agent states Chartr already receives. Broad coverage among supported agents, including Codex, without new Chartr-owned adapters. It can mistake cancellation or an unfamiliar screen for completion, miss requests, and cannot reliably label failures. Alerts would mean ‘may need attention.’

**Explicit terminal signals:** agents emit a bell or notification escape sequence. One common receiver, but silent agents need configuration or remain unsupported. This requests attention; it still does not prove success. Delivery through background Herdr sessions needs validation.

**Both:** use Herdr detection plus explicit signals. Potentially broader coverage, with extra routing and duplicate suppression. Herdr’s false-alert risk remains.
Recommendation: Start with existing Herdr detection. It best matches your priority of broad coverage with little Chartr-specific maintenance, if occasional false or missed alerts are acceptable.
Options: Existing Herdr detection; accept best-effort alerts / Explicit signals only; accept setup and coverage gaps / Both Herdr detection and explicit signals
Selected: Existing Herdr detection; accept best-effort alerts
```

## Question 16

```text
Round: Simpler agent attention
Question: After a terminal notifies me, when should it notify again?
Description (Markdown source):
This controls repeated desktop notifications. The dot would still remain until you focus that terminal in an active Chartr window. Unchanged status updates would never count as new events.
Recommendation: Notify once until you visit the terminal, so an unattended agent cannot keep interrupting you.
Options: Only after I visit that terminal / For each new attention event, even while its dot is unread
Selected: Only after I visit that terminal
```
