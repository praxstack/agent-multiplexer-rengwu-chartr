## Question 9

```text
Round: Agent attention — architecture after research
Question: Which detection direction should guide the design?
Description (Markdown source):
We studied the accessible implementations you listed, plus cmux. The reusable pattern is a shared attention interface. Dependable signals still need to come from the agent or a detector that understands it.

| Examples | Observed approach |
| --- | --- |
| [Zed terminal threads](https://zed.dev/docs/ai/terminal-threads) | A terminal bell requests attention; some agents need configuration or an extension. |
| [Tern](https://docs.stencil.so/tern/reference/api-window.html#agent-cx) | Working/waiting state comes from explicit progress OSC and ask overlays. |
| [cmux](https://cmux.com/docs/notifications) | Shared terminal notification sequences or CLI/hooks. |
| Kero and Orca | Agent-specific lifecycle integrations behind common UI behavior. |
| T3 Code, Synara and bb | Native provider/ACP integrations normalized into common state and events. |
| Herdr GPUI | Consumes Herdr daemon events; the GUI does not build another detector. |

Cursor exposes lifecycle hooks, Conductor documents attention notifications, and Soft Machine's app source is private. Their public material did not establish a universal internal detector.

**Chartr already uses Herdr for agent state.** Reusing it avoids duplicating its agent-specific maintenance in Chartr. However, its current idle fallback and tab-based acknowledgment need work before we can claim they meet your requirements. Herdr has semantic events, but the event identity/evidence and connection path still need design.

**A terminal-signals-only design** consumes signals from any cooperating agent without screen recognition. It cannot detect completion or input requests from an agent that emits no dependable signal; configuration or an extension may still be required. A generic bell means attention, not necessarily successful completion.

Your settled rules apply to either choice: uncertain state remains unknown; dots appear on terminal and group; exact-terminal focus acknowledges; desktop alerts apply outside that focus. This is a design choice only; implementation remains out of scope.
Recommendation: Reuse Herdr's detection boundary and keep Chartr's attention policy independent of agent names. Prefer explicit evidence, exclude uncertain fallback, and resolve backend gaps in that shared boundary.
Options: Reuse Herdr with conservative attention events / Use standard terminal signals only; accept coverage limits
Selected: Reuse Herdr with conservative attention events
Notes: yep i like reusing herdr, but what exactly we need to do to achieve the dots and notifications?
```
